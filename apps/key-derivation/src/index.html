What is checked?

BIP39 derives a 64-byte seed from the phrase and its BIP39 passphrase. MHFE draws fresh random phrases until the first two bytes of the tagged hash of that complete seed are zero: SHA-256("MHFE-WALLET-CHECK-SEED-1" || BE32(256) || seed). Neither the words, their entropy nor the seed is zeroed.

The check needs the BIP39 passphrase entered below, confirmed here: without one it would let anyone who sees the phrase test it. Keep the phrase and the passphrase for recovery, and keep all funds under this passphrase, since the wallet without it stays empty. Generation keeps the passphrase field unchanged.

The check takes 16 bits of choice from the phrase's 256; a chosen word and words never to use take more, as stated below before the phrase is drawn. Generation takes about 65,536 trials on average, has no fixed completion time, and can be cancelled. Only a phrase meeting every selected condition is returned.

This check is not encryption or proof of the wallet's identity. A wrong password or passphrase can pass about once in 65,536; compare a known address or fingerprint too. More: “mhfe new” in the mhfe README.

Not recommended. A phrase from the ordinary Generate buttons is the strongest. A word at a position takes about 11 of the phrase's random bits, a word anywhere about 7: that much less to search for someone who knows or guesses it, so never write it down next to the phrase.

The phrase is still drawn with crypto.getRandomValues(), evenly among all phrases that meet the wishes; the checksum is calculated, never chosen.

MHFE encrypted BIP39 backup

            

          

          

          

            What is this?
            

              
Memory-Hard Feistel Encryption

              

                MHFE is an experimental encryption construction designed by this project's author. It turns a
                checksum-valid 12-, 15-, 18-, 21-, or 24-word English BIP39 phrase into a password-protected container
                that is itself a checksum-valid BIP39 phrase, without storing a salt, nonce, or tag: 24 words by
                default, or as long as a 12- to 21-word phrase on request. It runs twelve Feistel rounds, each with
                Argon2id over 2 GiB of memory, so every recovery deliberately takes minutes; an encryption decrypts its
                result once more to check it and takes twice as long.
              

              

                In a 24-word container a shorter phrase carries a built-in check that confirms the password and finds
                the length. A 24-word phrase fills the whole state and has none, and neither has a container of the same
                length as its phrase: a wrong password then gives another valid phrase, so compare the result with your
                wallet.
              

              

                In this HTML version the browser runs Argon2 on one thread. The executable version of this tool opens
                the same page with four threads, about two and a half to three times faster. The browser supports memory
                level 0 (2 GiB); higher levels need the mhfe command-line tool.
              

              
Operations

              

                Encode and Decode encrypt a phrase and recover it. Check rehearses a recovery without showing the
                phrase. New wallet draws a new 24-word phrase and encrypts it. Change password moves a phrase into a new
                container. Hidden wallets shows the wallet another password opens. Repair mends a damaged container
                phrase with its repair words. Password makes a strong password. Self-test compares this page with the
                published vectors. Long operations start only when you press their button and can be cancelled.
              

              
Not in this page

              

                Memory levels above 0 need more memory than a browser gives WebAssembly. The check of free memory, the
                private terminal screen, the swap warning and the process protections of the mhfe program (no core
                dumps, locked memory, no network, no file writes) need the operating system: this page conceals secrets
                instead and ends each worker with its memory when its operation ends. Time estimates of settings,
                reading from standard input, exit codes and the long vector replays serve the command line and scripts.
                The executable version of this tool serves this page in fast mode, as mhfe serve does.
              

              
What the browser cannot wipe

              

                Passwords and passphrases you type, and the phrases, passwords, repaired containers and check-word
                answers this page shows, are JavaScript strings, which the browser cannot erase. The page empties
                password fields as soon as an operation starts, removes a compared phrase after your answer and stores
                nothing; close the tab when you are done.
              

              

                Read the
                MHFE specification
                and inspect the
                reference implementation. This page embeds the MHFE 0.6.0 browser package: suite MHFE-BIP39-256-EXPERIMENTAL-3 for 24-word
                containers and MHFE-BIP39-LP-EXPERIMENTAL-4 for containers of the phrase's own length.
              

            

          

          

          

            
            
            
            
            
            
            
            
            
          

          

            

              
              
            

            
            

              Container length
              
              
            

            

              

                24 words tell you when a password is wrong and hide how long your phrase is. The same length keeps the
                backup as short as the phrase, but cannot tell a wrong password, shows the length, and lets a miscopied
                word through more often.
              

              

                More details
                

                  
24 words or the same length?

                  

                    A 24-word container holds a 12- to 21-word phrase together with a built-in check. Recovery then
                    reports a wrong password or PIM, and the container does not show how long the phrase is. This is
                    suite MHFE-BIP39-256-EXPERIMENTAL-3, the same as for a 24-word phrase.
                  

                  

                    A same-length container is exactly as long as the phrase, suite MHFE-BIP39-LP-EXPERIMENTAL-4. It has
                    no built-in check: any password gives another valid phrase, so every recovered phrase is shown as
                    not verified, and you confirm it with a known address or with the master key fingerprint shown under
                    it, which is computed without a BIP39 passphrase. A word copied wrongly still passes the BIP39
                    checksum about once in 16 for 12 words and once in 128 for 21 words, against once in 256 in a
                    24-word container.
                  

                  
A 24-word phrase always gives a 24-word container.

                Do you want a check that confirms the password at recovery?
                
                
              

              

                

                  More details
                  

                    
A phrase + passphrase check

                    

                      Without the check, every password opens a valid wallet, which serves decoys, and a recovery cannot
                      tell a wrong password.
                    

                    

                      With the check, the phrase is drawn so that it passes a 16-bit check together with the passphrase:
                      a wrong password passes about once in 65,536, a guess also needs the passphrase, and about 240
                      bits of the phrase remain. Keep all funds under this passphrase, since the wallet without it stays
                      empty. A decoy password passes only after about 65,536 tries, and only a check with the passphrase
                      tests it.
                    

                    

                      It is a draft profile, MHFE-WALLET-CHECK-SEED-1, for new wallets only. A phrase that passes is
                      statistical evidence that MHFE prepared it.
                    

                    
More: “mhfe new” in the mhfe README.

            What is this?
            

              
SLIP-39 mnemonic shares

              

                Splits secret entropy into standardized mnemonic shares with a threshold. In a 2-of-3 set, any two cards
                recover the secret while one card is insufficient. Each share uses the separate SLIP-39 wordlist.
              

              

                An open-source reference implementation and its official vectors are used. Source code is available from
                Trezor python-shamir-mnemonic. The browser port is maintained by this project. Every build verifies locked dependency checksums.
                When GitHub is available, it also verifies the exact pinned upstream commit; a mismatch stops the build.
              

            

          

          

            SLIP-39 shares have their own 1024-word list, metadata and checksum. They are not BIP39 seed phrases.
          

          

            
            
          

          

            

              
            

            
            

              

                
              

              

                
              

              

                
              

            

            
            
            

              Use the current extendable format for new backups. Select legacy only when compatibility with older
              SLIP-39 software requires it.
            

            

              Compatibility boundary. These shares preserve the entropy of the BIP39 phrase so this
              tool can reconstruct the same words. A wallet that treats them as a native SLIP-39 wallet may derive a
              different wallet.

MnemoCode
