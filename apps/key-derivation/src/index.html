What is this?

Wallet Matcher / Derivation Discovery

Finds which candidate recovery phrase produced a known public address and reports its coin, account, branch, index, and complete derivation path. All candidates are tested locally in this file.

Example: enter the public test phrase “abandon … about” and one address derived from it. A match such as m/84'/0'/0'/0/5 identifies the fifth Native SegWit receive address.

SeedSigner SeedQR

            

          

          

            What is this?
            

              
SeedQR

              

                Converts a BIP39 recovery phrase into a QR payload for offline transfer or paper backup. Standard SeedQR
                stores four digits per word; CompactSeedQR stores the underlying entropy bytes.
              

              

                Example: the public test phrase “abandon … about” becomes 48 decimal digits in Standard
                mode. This is encoding, not encryption: anyone who scans the QR obtains the wallet secret.
              

            

          

          

            Standard SeedQR encodes four decimal digits per BIP39 English word. CompactSeedQR encodes the underlying
            entropy bytes. Both modes accept every standard 12-, 15-, 18-, 21-, and 24-word English BIP39 phrase.
            SeedSigner documents 12- and 24-word payloads; intermediate lengths work within this tool but may not be
            accepted by every external SeedQR implementation.
          

          

            Secret QR. Anyone who scans this QR can recover the wallet. Do not photograph, upload, or
            display it near cameras.
          

          

            
            
          

          

            

              
              
            

            
            
            
            

              
              
            

            

          

          

            
            
            
            
            

              
              
            

            

          

        


        

          

            

              02
              
SLIP-39 mnemonic shares

            

          

          

            What is this?
            

              
SLIP-39 mnemonic shares

              

                Splits secret entropy into standardized mnemonic shares with a threshold. In a 2-of-3 set, any two cards
                recover the secret while one card is insufficient. Each share uses the separate SLIP-39 wordlist.
              

              

                Example: “abandon … about” can become three unrelated-looking SLIP-39 cards. Combining
                card 1 with card 3 reconstructs the original BIP39 words in this workspace.
              

            

          

          

            SLIP-39 shares have their own 1024-word list, metadata and checksum. They are not BIP39 seed phrases.
          

          

            
            
          

          

            

              
            

            
            

              

                
              

              

                
              

              

                
              

            

            
            
            

              Use the current extendable format for new backups. Select legacy only when compatibility with older
              SLIP-39 software requires it.
            

            

              Compatibility boundary. These shares preserve the entropy of the BIP39 phrase so this
              tool can reconstruct the same words. A wallet that treats them as a native SLIP-39 wallet may derive a
              different wallet.
            

            

              
            

            

          

          

            

              
              
            

            
            
            
            
            

          

        

        

          

            

              02
              
Shamir Raw

            

          

          

            What is this?
            

              
Shamir Raw

              

                Uses the pinned Rust sharks implementation to split BIP39 entropy with Shamir Secret Sharing. Cards are
                compact Base64URL strings protected by CKD version, set, length, and checksum metadata.
              

              

                Example: a 2-of-3 split of “abandon … about” creates three opaque cards. Any two
                restore the phrase here; one card reveals no usable wallet seed. This is a CKD format, not SLIP-39.
              

            

          

          

            Uses the pinned Rust sharks GF(256) implementation. Shares are versioned Base64URL records for files, QR
            codes, or exact copy/paste.
          

          

            
            
          

          

            

              
            

            
            

              

                
              

              

                
              

            

            

              Format boundary. CKD Shamir Raw is not SLIP-39 and is not a native wallet import format.
              Keep each complete versioned record.
            

            

              
            

            

          

          

            

              
            

            
            
            

          

        

        

          

            

              02
              
Shamir Words

            

          

          

            What is this?
            

              
Shamir Words

              

                Uses the same pinned Rust Shamir shares as Raw mode, then represents each checksummed CKD envelope with
                familiar English BIP39 vocabulary for easier transcription.
              

              

                Example: a 2-of-3 split of “abandon … about” produces three word cards. Any two restore
                the original phrase here. A single card is not a valid BIP39 mnemonic and must not be imported alone.
              

            

          

          

            Uses the same pinned Rust sharks shares, encoded with familiar words from the BIP39 English list for
            transcription.
          

          

            
            
          

          

            

              
            

            
            

              

                
              

              

                
              

            

            

              Format boundary. The words encode a CKD Shamir share; they are not valid BIP39 seed
              phrases and are not compatible with SLIP-39.
            

            

              
            

            

          

          

            

              
            

            
            
            

          

        

        

          

            

              02
              
Codex32 · BIP93

            

          

          

            What is this?
            

              
Codex32 · BIP93

              

                Encodes secret bytes in a checksummed, error-correcting Bech32-style string and can optionally split
                them with Codex32 native shares. This workspace supports BIP39 entropy and BIP32 master-seed modes.
              

              

                Example: entropy mode can encode “abandon … about” and later restore its words.
                Master-seed mode first applies the BIP39 passphrase and cannot be reversed back into the mnemonic.
              

            

          

          

            Encodes either recoverable BIP39 entropy or a passphrase-derived BIP32 master seed with the Codex32
            error-correcting checksum and optional native secret sharing.
          

          

            
            
          

          

            

              
              
            

            
            
            
            

            
            
            

              

                
                
              

              

                
                
              

              

                
                
              

            

            
            
Disables the threshold and share-count fields.

              used when the backup was created.
