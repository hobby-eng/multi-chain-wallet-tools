# Wallet Discovery Scanner

Network-enabled standalone scanner that derives Dash Core receive/change addresses, Platform payment addresses, Platform identities and an Orchard account locally from one or several BIP39 phrases. Build output: `dist/discovery-scanner/Wallet_Discovery_Scanner.html`.

Dash Core recovery always scans both BIP44 branches—receive `/0` and change `/1`—with independent post-use gap tracking. This is not controlled by the optional change-display checkbox in the separate offline Wallet Key Derivation Tool: a recovery scan must include change addresses so it does not miss spendable funds returned by earlier transactions.

The single HTML contains two browser security realms. The visible application runs in a sandboxed `srcdoc` **Secret Vault** without `allow-same-origin` or `allow-downloads`; its CSP sets both `connect-src 'none'` and `worker-src 'none'`, so the realm that receives the mnemonic, passphrase, seed and FVK cannot open a network connection, create a worker, or initiate a download. A separate outer **Network Worker** embeds Evo SDK and owns every `fetch`/DAPI operation. The vault can reach it only through a transferred `MessagePort` whose typed protocol exposes eight fixed read operations; it accepts no arbitrary URL, request body, SDK method name or executable callback. Core RPC input is decoded as network-bound Base58Check P2PKH; Platform input is decoded as network-bound Bech32m DIP18 P2PKH. Identity queries remain a deliberate 20-byte HASH160 channel because those values are the actual public lookup keys. Scanner-specific validators check every structured-clone response before it affects balances. The existing `SecretEgressGuard` remains as a second tripwire before public RPC arguments leave the vault, but browser-realm/CSP separation—not pattern matching—is the primary boundary.

This independent scanner integrates the official open-source Dash Platform Evo/WASM SDK, specifications and Dash Orchard fork without claiming upstream authorship or endorsement. See the repository [attribution](../../ATTRIBUTION.md) and [third-party notices](../../THIRD_PARTY_NOTICES.md).

Original project code is released under the repository's [MIT License](../../LICENSE); embedded dependencies retain their separately listed licenses.

The Dash coin adapter is split into four scanners under `src/coins/dash`. Within every seed phrase, Core, Platform payment, identity and Orchard sections run concurrently while one shared FIFO semaphore caps all network work at five. Batch seed phrases are sequential by default; explicit concurrency from two through five remains available, but can increase DAPI tail latency. Trusted Evo SDK connection/quorum state is isolated by network and purpose (Platform addresses, identities, or Orchard), so one slow subsystem cannot monopolize another subsystem's SDK instance. Each proof call uses a 10-second SDK deadline, no hidden SDK retries, and at most two explicit fresh-connection retries with a short bounded backoff; deterministic invalid requests are not retried. Exhaustion fails the section and is never interpreted as a zero balance. In batch mode, each proof-verified encrypted Orchard page is downloaded once, applied to every local FVK, wiped, and discarded before the next page is requested. DAPI requires 2,048-action-aligned cursors, so a short page advances to the next aligned chunk rather than by its returned item count. Completion requires two proof-verified empty reads at the terminal cursor, and a 4,096-page safety ceiling produces `partial` rather than an unbounded scan. Per-seed progress rows show all active section stages without changing source-line result order.

The app-level registry, progress UI, per-seed result tabs and CSV/JSON export are protocol-neutral so Bitcoin and Ethereum can be added as separate adapters later. Export always covers all completed seed-phrase tabs and contains public recovery metadata only. Current-balance mode shows only funded Core/Platform resources and spendable incoming Orchard notes; the history switch additionally exposes zero-balance, spent and outgoing activity. Re-running after changing that switch creates a fresh run and replaces the prior report. Each wallet begins with a unit-safe aggregate overview, and zero-result messages explicitly name their section. Identity results include logical proof count, wall time, and DAPI average/maximum latency; Evo SDK 4.1.0 requires roughly two proof calls per empty identity candidate.

DashScan is the sole Core index in this build. The scanner requires its synchronization status to be `ok`, records the indexed Core height, and parses exact integer duff balances and transaction counts. This removes optional-provider outages, throttling, and disagreements from the recovery path, but it also means the Core result is single-source and not a consensus proof. The UI marks that limitation and instructs the user to verify every funded address in a standard Dash wallet before recovery.

```bash
pnpm build:discovery-scanner
node apps/discovery-scanner/scripts/verify-discovery-scanner-artifact.mjs
```

The build fails if the vault bundle contains Evo SDK, the network service, or the direct browser-download helper, or if the Network Worker imports mnemonic/BIP39/derivation/guard modules. CSV/JSON report text crosses a separate fixed export message; the trusted shell chooses the filename/MIME and creates a local Blob, while the vault receives only success/failure. Artifact verification independently checks the opaque sandbox flags, both CSPs, SHA-256-authorized inline scripts, fixed RPC operation set, absence of direct network/download primitives in vault source, absence of arbitrary-URL RPC input, exactly one pinned Orchard WASM, forbidden signing/broadcast calls, and the HTML checksum. Startup keeps scanning disabled until it proves that the vault cannot read its parent DOM, sees its own network- and worker-denied CSP, completes cryptographic tests including fixed DIP13 vectors, and receives the expected Network Worker handshake.

The scanner does not construct, sign or broadcast recovery transactions. Restore found funds with a standard wallet after independently verifying the public address/path. Read [SECURITY.md](SECURITY.md) before entering any phrase into this connected application.
