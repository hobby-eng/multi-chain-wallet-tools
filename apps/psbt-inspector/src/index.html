01

Define a multisig policy

Build one multisig/timelock spending script and funding address. This does not create a PSBT.

Script builder

BitcoinerLab validates types and compiles constants, key checks, timelocks, all four hashlocks, AND/OR/threshold combinators, and wrappers a s c t d v j n l u. P2WSH and Tapscript use different multisig/key rules: use multi() with compressed keys for P2WSH and multi_a() with x-only keys for Tapscript. The Taproot output uses Scure BTC Signer's standard unspendable NUMS internal key and one script leaf.

Local 32-byte preimage & HTLC commitment calculator

Miniscript hashlocks require exactly 32 preimage bytes. A phrase with another UTF-8 length is first normalized to 32 bytes with SHA-256; the displayed commitments hash that 32-byte value.

A 2-of-3 policy should normally use public keys whose corresponding private keys are controlled on separate devices.

Advanced shapes are custom scripts: HODL, HTLC-like hashlock, flexible, decaying, expanding, recovery multisig, backup committee, and staged/escalating timelocked recovery are compiled by BitcoinerLab Miniscript, but wallet auto-signing support varies. Staged recovery also accepts ranged xpub expressions; Scure BIP32 derives the selected branch/index while the exported descriptor remains ranged. OP_RETURN and vault/cancel covenant-style flows remain excluded.

Dash HD multisig: current Dash Electrum supports legacy P2SH cosigner keys at m/45'/0 (only partially BIP45-compatible) and its Purpose48 P2SH convention at m/48'/5'/account'/0', followed by /change/address_index. The builder accepts already-derived public keys, so a derivation path is recovery metadata and is not encoded in the resulting P2SH address.

01

Build an offline multisig wallet

Construct one concrete multisig script from fixed public keys, or derive a deterministic watch-only range from account-level public keys with explicit origin metadata.

Watch-only
Branches

Input is detected automatically. If every line is a compressed child public key, the utility builds one concrete address. If every line is an xpub/tpub, it derives the selected receive/change range; default range is the first 20 receive and change entries.

Automatic mode: child public keys produce one concrete m-of-n address; account xpubs produce a deterministic ranged watch-only wallet. BIP67 sortedmulti() is selected by default because it is the usual deterministic multisig policy; switch to supplied-order multi() only when matching an existing wallet that used that exact order.

Results regenerate automatically after changing keys, signature threshold, network, ordering, wrapper, branches, or index range.

Standard Dash P2SH multisig path: use BIP48-style Purpose48 account keys at m/48'/5'/account'/0' for Dash mainnet legacy P2SH multisig. This is the standard HD multisig separation pattern m/48'/coin_type'/account'/script_type', not an Electrum-only private address scheme. Do not mix it with legacy multisig keys from m/45'/0 or regular Dash Core BIP44 account xpubs at m/44'/5'/account'; those are different HD branches and intentionally produce different multisig scripts and addresses.

Mainnet/testnet xpubs differ: Dash mainnet Purpose48 uses m/48'/5'/account'/0' and exports xpub...; Dash testnet uses m/48'/1'/account'/0' and exports tpub.... Do not switch a mainnet xpub into testnet mode.

Concrete Dash multisig keys: when manually building one standard P2SH multisig address, use one child public key from each cosigner's Purpose48 branch at the same suffix, for example m/48'/5'/0'/0'/0/0. If you paste xpubs instead, the first row is receive /0/0. Do not use ordinary single-sig BIP44 child keys such as m/44'/5'/0'/0/0 unless you intentionally want a nonstandard wallet policy that may be harder to restore.

What P2SH uses: individual single-signer receive addresses are not part of the multisig wallet. Each shared P2SH address is derived from the child public key of every cosigner at the same branch/index, then hashed as one redeemScript. A watch-only wallet needs the cosigner xpubs and origin paths; private keys are needed only by signers when spending.
