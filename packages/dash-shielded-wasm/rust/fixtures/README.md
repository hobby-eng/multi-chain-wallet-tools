# Official Platform wallet fixture

`official-platform-wallet-note.json` is a fixed scanner-compatibility fixture captured from the official Dash Platform wallet source, not generated by this repository's scanner tests.

## Provenance

- Repository: [`dashpay/platform`](https://github.com/dashpay/platform)
- Stable release: [`v4.1.1`](https://github.com/dashpay/platform/releases/tag/v4.1.1)
- Commit: [`69b85c81af8e000e8506edaa13406d1f6274af5a`](https://github.com/dashpay/platform/commit/69b85c81af8e000e8506edaa13406d1f6274af5a)
- Source test: [`packages/rs-platform-wallet/src/wallet/shielded/sync/shield_decrypt_tests.rs`](https://github.com/dashpay/platform/blob/69b85c81af8e000e8506edaa13406d1f6274af5a/packages/rs-platform-wallet/src/wallet/shielded/sync/shield_decrypt_tests.rs)
- Orchard dependency: the release lockfile pins the same `dashified-0.14.1` tag and `38ac9c19a2df7bf3eeadc22ab23053e8fd538828` commit used by this project
- Wallet path: `build_shield_transition`, followed by the official recipient-IVK recovery check
- Toolchain: Rust 1.92 in `rust:1.92-bookworm` image digest `sha256:e90e846de4124376164ddfbaab4b0774c7bdeef5e738866295e5a90a34a307a2`
- Captured: 2026-09-04

The upstream test uses the synthetic testnet seed `[0x42; 32]`, account zero, 200,000,000,000 Platform credits, and an empty 36-byte Dash memo. The wallet sends to its own default Orchard address and encrypts the outgoing ciphertext with its own OVK, so the same complete action exercises both incoming FVK recovery and outgoing OVK recovery. These are public test inputs and control no real funds. Orchard action encryption is network-independent; testnet affects only the ZIP32 coin-type key derivation and avoids presenting the fixture as a real mainnet wallet.

The official test was run unchanged except for the output-only instrumentation in `capture-platform-wallet-fixture.patch`. It selects the one action that decrypts for the recipient and emits the recipient FVK, own OVK, raw recipient, value, memo, and the complete `cmx`, action nullifier, `cv_net`, and 216-byte `encrypted_note`. The test still had to pass its original recipient-IVK assertion before its output was accepted here; this repository separately pins outgoing recovery because the official builder configured that action with the wallet's own OVK.

```sh

git -C platform checkout 69b85c81af8e000e8506edaa13406d1f6274af5a

curl --fail --location \
  https://github.com/protocolbuffers/protobuf/releases/download/v32.0/protoc-32.0-linux-x86_64.zip \
  --output platform/protoc-32.0-linux-x86_64.zip

docker run --rm --network host \
  -v "$PWD/platform:/platform" -w /platform \
  rust@sha256:e90e846de4124376164ddfbaab4b0774c7bdeef5e738866295e5a90a34a307a2 \
  sh -c 'apt-get update -qq &&
    apt-get install -y -qq --no-install-recommends \
      build-essential clang llvm libsnappy-dev cmake libgmp-dev \
      libssl-dev pkg-config jq zip unzip curl &&
    echo "7ca037bfe5e5cabd4255ccd21dd265f79eb82d3c010117994f5dc81d2140ee88  /platform/protoc-32.0-linux-x86_64.zip" |
      sha256sum --check --strict &&
    unzip -q /platform/protoc-32.0-linux-x86_64.zip -d /opt/protoc &&
    export PATH="/opt/protoc/bin:$PATH" CC=clang CXX=clang++ &&
    test "$(protoc --version)" = "libprotoc 32.0" &&
    cargo test -p platform-wallet --features shielded \
      shield_built_note_is_trial_decryptable_by_own_ivk \
      -- --nocapture'
```

The wallet builder uses operating-system randomness, so another valid run will produce different ciphertext bytes. This committed output is therefore an immutable external wallet compatibility pin, not an upstream-published deterministic cryptographic test vector and not evidence of an independent Orchard implementation. The local scanner test never regenerates it. Position `42` is synthetic scanner metadata; it is not part of the encrypted action.
