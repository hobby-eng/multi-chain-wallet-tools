- Added MnemoCode cross-stitch patterns (SeedStitch): Encode hides the phrase, masked with MnemoCode Seedshift and its dates or with Direct the phrase itself, in the legend of a DMC cross-stitch pattern made from a PNG, JPEG or WebP picture, on Aida 11 to 18 or linen 28 over one, at a sheet size from A6 to A2 or a width typed in centimetres or stitches, and saved as a PDF that looks bought; Decode and Re-encode read the legend line from that PDF or as typed, and they and Forgotten's date search correct one mistyped row and name it.
- Added the Photo or MP3 tab, MnemoCode's steganography: a message, a small file or a MnemoCode backup record hidden in a JPEG photograph or an MP3 file under a container password, optionally with a decoy under a second password, or divided across 2 to 16 files of which a quorum recovers it. The guaranteed space at every density is shown first; every new file is read back from the Blob saved and opened with each password before it is offered. Encode's records and a pattern's legend line can be hidden there, and what it opens goes on to Decode or Re-encode. Once a new file is saved, the page asks, as MnemoCode does, that each source be kept private: encrypted if it is used again, or else deleted with its cloud copies, since a source and its saved file compared show the hidden changes. It is not statistical invisibility; recompression or resizing destroys the record.
- Added MnemoCode's QR codes with a hidden record: a card sheet's QR can show the printed contact to ordinary scanners and keep the record in its hidden bytes, and every MnemoCode QR image import reads such a record first. It is camouflage, not encryption.
- Added SeedQR hidden in a decoy QR: on the SeedQR tab, Encode offers an ordinary SeedQR or a Standard SeedQR kept as the hidden record of MnemoCode's hidden QR, behind a decoy that ordinary scanners show instead (other wallets cannot read the SeedQR: they show the decoy or reject the code): a contact card (vCard 3.0), a website, a plain text, a Wi-Fi network, an email, a phone number or a location, each with its own fields and its format's escaping. CompactSeedQR, raw bytes rather than text, is not hidden. Save PNG gives MnemoCode's own image, to print at actual size; Decode's image import reads its hidden record first and restores the phrase, and refuses a hidden record that is no SeedQR. A PNG beyond MnemoCode's 4096 pixels a side or 2 megapixels, such as a phone screenshot of an ordinary SeedQR, is read as an ordinary QR again, on the SeedQR tab and on MnemoCode's tabs alike, and a note under the field says that its hidden record went unread. It is camouflage, not encryption: protect the phrase first, for example with the SeedQR of an MHFE container phrase.
- Added MHFE 0.8.0 (suites `MHFE-BIP39-256-EXPERIMENTAL-3` and `MHFE-BIP39-LP-EXPERIMENTAL-4`), an experimental encryption of a BIP39 phrase into a password-protected 24-word container, or on request into one as long as a 12- to 21-word phrase: twelve rounds of Argon2id with 2 GiB each, PIM 0–1023, and a check of every new container before it is marked verified. Opened as a file, the page runs Argon2 on one thread.
- Added MHFE's decrypt with several passwords: Decode asks every password, with its own PIM and check-word repair, and for a 24-word container the original seed phrase's BIP39 passphrase for the 16-bit check, before any work, then recovers each password in turn and shows every seed phrase on one screen under its password.
- Added the memory level to MHFE's Encode: levels 0 to 21, each with its memory, of which a browser runs level 0 alone, so Encrypt is off above it. For a memory level or a PIM other than 0, Encode shows the `mhfe encrypt` command with the same settings and a Copy button, such as `mhfe encrypt --pim 3 --mem 2 --same-length --new-password check-word --repair-words 4`; a custom PIM at level 0 still encrypts in the page. Above level 0 the page makes no password, since mhfe makes its own. The command holds no secret: mhfe asks for the seed phrase and the password at its own prompts, so neither enters the command, the clipboard or the terminal history.
- Added the Desktop Deriver, `Dash_Community_Key_Derivation_Tool_Desktop-<platform>`, one program per platform (Linux x86-64 and ARM64, Windows x86-64, macOS ARM64 and x86-64). It is the whole Deriver: it carries the release page, checks its SHA-256 when it starts and serves it to this computer only, so that MHFE runs in fast mode with four threads, about two and a half to three times faster than the page opened as a file.
- Added bounded generation with one chosen BIP39 word, or one excluded word, with the remaining random bits shown before generating.
- Added an optional exact derivation path when recovering missing MHFE container words against a known address. The address scope is shown before searching; an invalid path is refused.
- Normalized every BIP39 phrase and passphrase with the Deriver's own NFKD of Unicode 18.0.0, the version MHFE's specification pins, instead of the browser's: a passphrase with a newly assigned character, such as U+209D, now gives the same seed in every browser, in MHFE and in MnemoCode. The tables are generated from Unicode's `UnicodeData.txt` and checked against all of its `NormalizationTest.txt`.
- Added an explicit MHFE wallet-check checkbox: the Deriver's own generator samples phrases, on the workers you choose (Threads, 2 at first, on WebCrypto's PBKDF2; further threads in JavaScript), until the first two bytes of the check derived from the complete BIP39 seed are zero, and MHFE's wallet module checks the phrase once more before it is shown; it uses the phrase and the nonempty BIP39 passphrase of the one passphrase field, which asks you to check it with Show. The phrase and seed bytes are not overwritten. Hover or click the adjacent “?” to read the explanation.
- The wallet check says before the start how long a phrase takes on this computer, from a one-second measurement after an option changes.
- Every Generate shows a line under its buttons from the click on: what is drawn, the draws tried, the time and the average time at the speed so far, Stop for a draw that can last, and how it ended. A refusal of generation appears there too, not at the derivation's messages.
- Added a “?” with an explanation beside the options whose meaning is not plain at once: the derivation types, child seeds, legacy mobile Core and CoinJoin addresses in the Deriver, the custom PIM of every MHFE form, an unsplit Codex32 secret, and the PSBT Inspector's output wrapper, policy shape, key order, timelocks, hashlock, ranged keys and script kinds. A help stays inside the window at every width.
- Added seed diagnostics before backup encoding and for recovered phrases.

- Added Dash Platform identity funding keys (DIP13) to the Deriver: the Dash Core addresses and keys at `m/9'/5'/5'/1'…5'/index` that fund identity registration, identity top-ups (for any identity, and bound to one identity), invitations, and Platform address and shielded pool top-ups. The invitation key is shown both ways, with the normal index of the Dash mobile wallets, Dash Evo Tool and the Platform wallet, and with the hardened index of the DIP13 text and Dash Core v24.

## Download and verify

Download the files you need into one folder together with `SHA256SUMS`, the release's one checksum file, and check them there. Every file you downloaded must be reported `OK`; `--ignore-missing` skips the release files you did not download:

```bash
sha256sum -c SHA256SUMS --ignore-missing        # Linux
shasum -a 256 -c SHA256SUMS --ignore-missing    # macOS
```

On Windows, run `Get-FileHash <file>` in PowerShell and compare the hash with the file's line in `SHA256SUMS`; `Get-FileHash` prints upper-case hex, so compare without regard to case. `Dash_Community_Key_Derivation_Tool_Desktop-<platform>` is the whole Deriver, served to this computer only so that MHFE runs in fast mode: take the one for your system and allow it to run with `chmod +x` on Linux and macOS. `gh attestation verify <file> --repo hobby-eng/dash-wallet-tools` checks, with the network, that GitHub built a file from this repository.

## Safety notes

Use the Deriver and Inspector offline for sensitive material. Connected lookups reveal queried public identifiers and source IP addresses to providers. Orchard viewing keys reveal wallet activity even though they cannot spend. Recovery records and private exports must be protected according to their threshold/access design. Restore and move valuable funds with a maintained Dash wallet after independently confirming the displayed paths, keys, addresses, and balances. MHFE is experimental and not independently reviewed.
