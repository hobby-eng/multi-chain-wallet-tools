## Results

1. **AUD-015-FUN001** — The Dash parser must interpret PSBT keys in version context. The upstream PSBTv0 `0x0f` example is an unknown passthrough field; it must be displayed and preserved rather than treated as a missing PSBTv2 output index. This is covered by the pinned Dash vector suite.
2. **AUD-015-FUN002** — The official BIP67 P2SH address and redeem-script vectors match the project implementation.
3. **AUD-015-FUN003** — Multisig account origins belong to each cosigner independently. Valid mixed origin paths are preserved; they are not rejected merely because paths differ.
4. **AUD-015-DOC001** — `m/44'/5'/0'` is Dash Core's default mainnet pkh signer account. A nonzero BIP44 account is valid custom material, but an ordinary account-0 signer will not infer its private keys from PSBT origin metadata. The UI therefore distinguishes account 0 from custom accounts and requires matching signer material.
5. **AUD-015-DOC002** — Purpose48 remains an explicitly wallet-specific P2SH convention. Dash Core does not define it, so the project does not present it as a Core standard.
6. **AUD-015-BLD001** — Generated `dash-cli` commands now include the selected testnet/regtest flag, create a blank descriptor watch-only wallet with `load_on_startup=true`, and import active receive/change ranges with `next_index`.
7. **AUD-015-FUN004** — P2SH keeps its 15-compressed-key practical script-size limit. The shared Bitcoin P2WSH path separately supports up to 20 keys.
