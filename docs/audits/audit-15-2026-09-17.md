# Independent source and interoperability audit

Date: 2026-09-17. Scope: Dash Core PSBT decoding, descriptor multisig import, cosigner derivation and the corresponding build profiles. The review compared this project with `dashpay/dash` source and official fixtures. It did not modify upstream code or use real wallet secrets.

Reviewer model: GPT-6 Astra. The reasoning-effort setting was not retained and is therefore not guessed here.

## Sources and method

- Dash Core source at commit `3a0c9383525ab16f12309989458deff9f533c8d9` for descriptor-wallet key paths and signing-provider behavior.
- Dash Core `test/functional/data/rpc_psbt.json`, pinned in the repository with its source commit and SHA-256.
- Dash Core `test/functional/data/rpc_bip67.json`, four official P2SH sorted-multisig vectors, pinned with SHA-256.
- Dash Core functional unknown-key PSBT vector, which requires byte-for-byte passthrough of an input field that is unknown in the PSBTv0 context.
- Project type checks, unit tests, artifact verifiers and selective build profiles.

## Results

1. The Dash parser must interpret PSBT keys in version context. The upstream PSBTv0 `0x0f` example is an unknown passthrough field; it must be displayed and preserved rather than treated as a missing PSBTv2 output index. This is covered by the pinned Dash vector suite.
2. The official BIP67 P2SH address and redeem-script vectors match the project implementation.
3. Multisig account origins belong to each cosigner independently. Valid mixed origin paths are preserved; they are not rejected merely because paths differ.
4. `m/44'/5'/0'` is Dash Core's default mainnet pkh signer account. A nonzero BIP44 account is valid custom material, but an ordinary account-0 signer will not infer its private keys from PSBT origin metadata. The UI therefore distinguishes account 0 from custom accounts and requires matching signer material.
5. Purpose48 remains an explicitly wallet-specific P2SH convention. Dash Core does not define it, so the project does not present it as a Core standard.
6. Generated `dash-cli` commands now include the selected testnet/regtest flag, create a blank descriptor watch-only wallet with `load_on_startup=true`, and import active receive/change ranges with `next_index`.
7. P2SH keeps its 15-compressed-key practical script-size limit. The shared Bitcoin P2WSH path separately supports up to 20 keys.
