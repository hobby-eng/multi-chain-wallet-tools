#### AUD-028-SEC001 — High — Envelope accepts noncontributory X25519 recipients

- **Category:** SEC
- **Severity:** high
- **Status:** open
- **Release blocking:** true
- **Affected files and builds:** `packages/recovery-envelope-wasm/rust/src/lib.rs:123`; `packages/recovery-envelope-wasm/rust/src/lib.rs:148`; `packages/recovery-backup/src/gordian-envelope.ts:66`; `apps/key-derivation/src/ui/recovery-gordian-envelope.ts:103`
- **Reproduction:** Run the bounded Envelope recipient conformance harness against the committed WASM. Encode synthetic u=0 and u=1 as correctly checksummed agreement-public-key URs; call recipient-only protected creation with public entropy and TREZOR.
- **Expected behavior:** Reject a recipient that produces an all-zero X25519 shared secret before returning any protected record. Preserve correct recipient and SSKR recovery.
- **Observed behavior:** Both rejection assertions fail: protected records are returned. Independent Noble X25519 controls refuse both points. Two ordinary recipient private keys and a two-of-three SSKR quorum recover exact entropy and TREZOR; a wrong key/no permit refuse.
- **Impact:** The pinned bc-crypto path feeds the shared secret into HKDF without rejecting zero. For these points, the recipient wrapping key is therefore determined by public constants, so recipient-only confidentiality cannot be relied on; adding another permit does not repair a weak permit. This impact follows from the bound source path and cryptographic semantics. Independent decryption without a private key was not executed. Ordinary generated recipient keys were not shown defective.
- **Evidence:** envelope-recipient-conformance.command.json, envelope-recipient-conformance.log, crypto-contract-followup.command.json, crypto-contract-followup.log
