## Review evidence

### Scope and methodology

This review answers where wallet-tools repeats rules and what should own them. It found **34 coherent duplication families**, with **2–9 inspected definitions per repeated facet**, and **five distinct behavior defects reproduced by short probes**. A sixth medium finding is a static optional-feature invalidation trace. There are six medium and eight low new findings. The group register below gives exact source locations and a proposed owner, migration and focused verification for every family.

No global number of extra copies is reported: a profile, a width map and an entropy calculation are different facets; some share sites. Similar counters and missing checks are not additional duplicate definitions. The register is an inspected lower bound, not proof of an exhaustive semantic count.

The five reviewers had distinct scopes: Ohm reviewed core/coin/recovery parameters, Faraday the Deriver, Pascal Inspector and connected public flows, Nietzsche tooling/docs/distribution, and Banach independently challenged all 40 initial candidates after those inventories. The coordinator checked overlaps, exact source hashes and the five bounded reproductions. Reviewers ran no builds/tests; execution evidence belongs to the coordinator and was shared rather than repeated.

The owned-source inventory covers 558 TS/MJS/Rust files and 81,273 lines. AST screening considered 1,851 bodies meeting 35-node/6-line thresholds out of 4,993 function nodes. It found zero exact/identifier-renamed body clusters, 1,087 repeated-string groups, 1,784 resolved first-party import edges, no scoped unresolved imports and no runtime SCCs. There are 97 class declarations. These metrics are navigation aids: none proves DRY, good OOP, complete graph isolation or cryptographic correctness. Rust interfaces were reviewed manually; no Rust AST clone detector or full crate-body audit was run.

Generated/vendor code, wordlists, independent tests/oracles and the synced MnemoCode source are excluded from first-party clone counting. Local MHFE/MnemoCode adapters, manifests and composition boundaries were reviewed; upstream implementations and complete native/browser feature parity were not re-audited. Fast MHFE multithreading, both Argon2 files, launchers and Envelope's own Argon2 remain required.

The primary checkout is the original Git tree (`commonGitDir: .git`). All work stayed in place. No browser, full vector replay, full-size KDF, mass PDF/card rendering, Docker/native/WASM build, network provider query, install, CI dispatch or release action was run. Node heap was capped at 1,536 MiB and Vitest used one worker. Host memory snapshots stayed below 14 GiB used; this is not a continuous peak guarantee across other sessions.

Environment: Linux-7.0.0-38-generic-x86_64-with-glibc2.43; Node v26.10.0, pnpm 12.8.1, Python 3.14.4; installed TypeScript 7.0.2, Vitest 5.0.3, Prettier 3.9.9, Playwright 1.63.0 and esbuild 0.28.2. Playwright was not launched. Rust/Docker/browser execution versions were not sampled.

### Findings

#### AUD-024-SEC001 — Medium — Late BIP38 completion restores cleared secret results

- **Category / status:** SEC / open.
- **Release blocking:** true. Restore the supported Clear/secret publication guarantee before releasing this affected feature; medium reflects bounded demonstrated local impact.
- **Affected files and builds:** [apps/psbt-inspector/src/bip38-feature.ts:136](../../apps/psbt-inspector/src/bip38-feature.ts). Local composition as described; feature absence excludes its path.
- **Reproduction:** Execute the actual installer with a memory DOM and deferred synthetic decryptor. Start decrypt, Clear, then resolve; repeat with a replacement run started before the old result resolves.
- **Expected:** Clear revokes publication by the old operation. Old completion cannot create secret inputs, enable reveal or mutate a new password/status/progress state.
- **Observed:** After Clear the old completion retains two secret inputs and enables reveal while the result container stays hidden. After Clear plus a new run the old inputs are in the visible results and the replacement password is cleared.
- **Impact and limits:** A supported secret-lifetime operation is undone by pending work. Evidence is local DOM retention and cross-run mutation, not egress, unauthorized spending or proof of heap erasure failure.
- **Recommended fix:** Give the local BIP38 secret session an operation token. Check it after every await before success/error DOM writes and before password/reveal/progress finalization. Dispose stale mutable outputs; keep cryptographic values local.
- **Required verification:** Deferred success and rejection after Clear, old completion during a replacement run and idempotent disposal, using synthetic data without scrypt; then the nearest small Inspector lifecycle tests.
- **Evidence:** `docs/audits/AUD-024-evidence/bip38-clear.log` (local); SHA-256 `28c4e8a690ccbefa2142cc4870dd4863b691ceb317446df16ebf82c81a53698d`, exit 1. No browser, clipboard, real KDF or real wallet material. Rejection path was read but not separately executed.
- **Prior related findings:** AUD-022-SEC001, AUD-023-SEC002; different BIP85/recovery-card paths. Those IDs and their historical evidence are not replaced or newly verified.

#### AUD-024-BLD001 — Medium — Verification-record inventory reads a nested MHFE directory as a file

- **Category / status:** BLD / open.
- **Release blocking:** true. The supported mandatory record step must accept the current vendored package before release; unreleased-upstream provenance remains a separate gate.
- **Affected files and builds:** [tooling/create-verification-record.mjs:43](../../tooling/create-verification-record.mjs). Local composition as described; feature absence excludes its path.
- **Reproduction:** Execute exact generatedDirectories and wasm declarations from create-verification-record.mjs with real read-only fs on the current package tree, without running the entry point.
- **Expected:** Supported record generation enumerates all included nested package files deterministically, using the same admitted manifest as provenance.
- **Observed:** The enumeration fragment exits 1 with EISDIR for packages/recovery-mhfe-wasm/generated/core. It enumerates one level and attempts readFileSync on each entry.
- **Impact and limits:** The mandatory package inventory step cannot construct the current nested MHFE records. Full prerequisite checks and release entry point were not run; this is not a completed release failure or a secret-compromise claim.
- **Recommended fix:** Implement the VendoredMhfePackage extraction below. Include modules.json, nested core/runtime/repair/passwords/wallet files and both Argon2 engines; retain the documented helper exclusion. Do not merely skip directories.
- **Required verification:** Deterministic nested manifest fixture with exact expected paths and hashes, missing/extra/unsafe entries and both engines. Exercise supported record generation once prerequisites are met; full release procedure only when requested.
- **Evidence:** `docs/audits/AUD-024-evidence/mhfe-record-path.log` (local); SHA-256 `78b43588c73e775ad41b2d80c6a0f6c2b27f3e3c14516be48b8eba278dd9193d`, exit 1. Only extracted production enumeration declarations were executed, no dist writes or complete artifact pipeline.

#### AUD-024-FUN001 — Medium — Child-wallet totals above fifty bypass bounded derivation batches

- **Category / status:** FUN / open.
- **Release blocking:** false. No separate release-blocking conclusion from this bounded evidence.
- **Affected files and builds:** [apps/key-derivation/src/ui/streamed-derivation.ts:32](../../apps/key-derivation/src/ui/streamed-derivation.ts); [apps/key-derivation/src/ui/bip85-child-wallet-feature.ts:472](../../apps/key-derivation/src/ui/bip85-child-wallet-feature.ts). Local composition as described; feature absence excludes its path.
