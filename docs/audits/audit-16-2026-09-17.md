# Independent source and interoperability audit

Дата: 2026-09-17. Проверялись текущие исходники и существующий Multi-Chain HTML. HEAD проекта: `6756193fc579a9ab530678f8169f4ca9b8adbeb2`, плюс уже существовавшие незакоммиченные изменения. Это проверка рабочего дерева, а не только tree коммита. Код проекта, HTML и Git в ходе этой проверки не изменялись.

Модель и уровень рассуждения не были записаны в исходных материалах этой проверки; надёжно восстановить их задним числом нельзя.

**Результат:** обычный multisig и основной разбор PSBT проходят официальные векторы и реальный цикл подписания. Полного соответствия Bitcoin Core пока нет: ниже 13 воспроизводимых замечаний. P1 здесь означает высокий приоритет исправления ложных утверждений интерфейса о защите подписью, а не доказанную кражу ключей или средств.

## Remediation status

All 13 findings below were corrected in the same workstream. The repository now retains focused regressions for the official descriptor cases, proprietary-key envelopes, PSBTv2 lock alternatives, protocol selection, SIGHASH_SINGLE, ranged Taproot policies, mixed origins and 17/20-key P2WSH. The full verification and browser matrices passed after remediation; the detailed findings remain below as the review record for the pre-fix snapshot.

## Подтверждённые замечания

### B-01 · P1 · Legacy SIGHASH_SINGLE ошибочно помечает входы защищёнными

[signing-commitments.ts:108](../../apps/psbt-inspector/src/signing-commitments.ts).

При двух входах и одном выходе для второго Legacy-входа с `SIGHASH_SINGLE` интерфейс пишет `Current input: Committed` и `Other inputs: Committed`. Предупреждение об unusual policy присутствует, но эти два утверждения неверны. В этом историческом случае Legacy signature hash — константа ONE, не зависящая от полей транзакции. SegWit v0 ведёт себя иначе; Taproot без соответствующего выхода отвергает подпись.

Эталон: [SignatureHash](https://github.com/bitcoin/bitcoin/blob/a604a7647588500354d4772e60620ea36b129d05/src/script/interpreter.cpp#L1615). Проба: `additional-results.json`, `legacy_single_missing_output`; браузеры подтвердили текст.

Исправление: отдельные ветки для трёх протоколов; для Legacy не показывать защиту входов и явно описывать константный digest. Добавить тесты SINGLE/ANYONECANPAY и отсутствующего выхода.

### B-02 · P1 · Необязательные метаданные подменяют определение протокола подписи

[signing-commitments.ts:35](../../apps/psbt-inspector/src/signing-commitments.ts).

К настоящему P2PKH-входу с проверенным non-witness UTXO достаточно добавить валидный `PSBT_IN_TAP_INTERNAL_KEY`. Приоритет метаданных над scriptPubKey заставляет наш интерфейс писать `Taproot / BIP341` и `Current input amount: Committed`; для Legacy сумма в signature hash не входит. Core декодирует дополнительные метаданные, но они не превращают P2PKH в Taproot.

Эталон: выбор SigVersion по spending script и [SignatureHash](https://github.com/bitcoin/bitcoin/blob/a604a7647588500354d4772e60620ea36b129d05/src/script/interpreter.cpp). Проба: `legacy_input_with_taproot_metadata` в `additional-results.json`, оба браузера.

Исправление: определять протокол по привязанному UTXO и проверенной цепочке redeem/witness scripts. Противоречивые метаданные отмечать отдельно. При недостатке данных выводить неопределённость вместо уверенного утверждения. Это общий модуль; проверить также Dash, где эти поля вообще могут быть unknown.

### B-03 · P2 · Структура proprietary PSBT keys не проверяется

[psbt-validation.ts:54](../../apps/psbt-inspector/src/psbt-validation.ts).

Ключи `fc`, `fc00`, `fc036162` и ключ с неканонической длиной identifier принимаются в global/input/output maps. Core отклоняет их из-за отсутствующего identifier/subtype либо неканонического CompactSize. Всего 12 отрицательных проб дали расхождение, 3 корректных контрольных примера приняли обе реализации. У нас при этом отображается успешная проверка framing/field schema.

Эталон: [PSBT_IN_PROPRIETARY](https://github.com/bitcoin/bitcoin/blob/a604a7647588500354d4772e60620ea36b129d05/src/psbt.h#L900) и аналогичные global/output ветви. Доказательство: `additional-results.json`.

Исправление: разбирать структурную часть proprietary key через ограниченный Reader, проверять канонические длины и наличие subtype, сохраняя непрозрачные остаток key и value. Не запрещать корректные unknown-поля: они отличаются от повреждённого известного proprietary envelope.

### B-04 · P2 · Неправильная совместимость locktime в PSBTv2

[psbt-validation.ts:179](../../apps/psbt-inspector/src/psbt-validation.ts), [signing-commitments.ts:152](../../apps/psbt-inspector/src/signing-commitments.ts).

Вход с обоими полями `height=800000` и `time=1700000000` получает FAILED как несовместимый. BIP370 допускает оба вида как альтернативы. Когда допустимы оба, выбирается высота; смешение несовместимо лишь при требованиях, исключающих общий вариант. Кроме того, у нас отображается time вместо эффективной высоты.

Эталон: [ComputeTimeLock](https://github.com/bitcoin/bitcoin/blob/a604a7647588500354d4772e60620ea36b129d05/src/psbt.cpp#L86), [официальный тест с двумя альтернативами](https://github.com/bitcoin/bitcoin/blob/a604a7647588500354d4772e60620ea36b129d05/src/test/psbt_tests.cpp#L105), [BIP370](https://github.com/bitcoin/bips/blob/master/bip-0370.mediawiki#determining-lock-time). Доказательство: `edge-results.json`, оба браузера.

Исправление: единый расчёт эффективного nLockTime по всей транзакции; отдельные tests для dual/height-only/time-only, максимума и fallback. Core 31.1 этой пробой не подтверждался: он вообще не поддерживает v2.

### B-05 · P2 · Расширенные P2SH-пресеты экспортируют неподдерживаемые Core дескрипторы

[policy.ts:406](../../apps/psbt-inspector/src/policy.ts).

Все 9 проверенных расширенных P2SH-пресетов возвращают `sh(Miniscript...)`, названный в UI portable descriptor. Core принимает обычные P2SH `multi()/sortedmulti()`, но Miniscript внутри sh не поддерживает. Все 9 экспорта отклонены живым getdescriptorinfo. Это несовместимость экспортируемого формата и wallet workflow; само получение scriptPubKey/P2SH-адреса из такого скрипта не доказывает ошибку консенсуса.

Эталон: [грамматика ParseScript](https://github.com/bitcoin/bitcoin/blob/a604a7647588500354d4772e60620ea36b129d05/src/script/descriptor.cpp#L2723). Доказательство: `policy-matrix-results.json`.

Исправление: для переносимых Core-политик предлагать P2WSH/P2TR; для custom P2SH отделить raw watch-only descriptor, обязательный redeemScript и необходимость собственного проверенного signer. Не называть такой sh-экспорт импортируемым дескриптором Core.

### B-06 · P2 · Decaying / expanding пресеты также не импортируются в Core

[policy.ts:276](../../apps/psbt-inspector/src/policy.ts).

В этих пресетах одни и те же ключи повторяются в разных ветвях. Для P2WSH и P2TR Core отклоняет Miniscript как `not sane: contains duplicate public keys`. Локальный compiler тоже сообщает `not sane`, но builder всё равно создаёт funding address и portable descriptor. Поэтому простой переход с P2SH на P2WSH эти два пресета не чинит.

Эталон: [IsSane / CheckDuplicateKey](https://github.com/bitcoin/bitcoin/blob/a604a7647588500354d4772e60620ea36b129d05/src/script/descriptor.cpp#L2727). Четыре RPC-подтверждения: `policy-matrix-results.json`.

Исправление: либо совместимая с Core форма политики без запрещённых повторов с отдельной проверкой эквивалентности, либо явно отдельный advanced custom mode без обещания импорта. Нельзя просто выключить safety-анализ и считать совместимость восстановленной. Повтор ключей сам по себе здесь не доказательство возможности украсть средства.

### B-07 · P2 · Bitcoin ranged import не создаёт рабочий active multisig wallet

[multisig-wallet.ts:370](../../apps/psbt-inspector/src/multisig-wallet.ts).

Экспорт ставит `active:false`, не указывает next_index и не создаёт отдельный blank watch-only wallet. В чистом кошельке импорт проходит, но getnewaddress/getrawchangeaddress возвращают `This wallet has no available keys`. В ранее существующем кошельке остаются его старые active descriptors. Следовательно, пользователь может продолжить получать адреса другого типа кошелька.

Пассивный импорт для наблюдения сам по себе валиден; проблема в несоответствии полному сценарию создания ranged multisig. Эталон: [Core multisig workflow](https://github.com/bitcoin/bitcoin/blob/9be056a8a72b624dae9623b2f7bded92c2a21c91/test/functional/wallet_multisig_descriptor_psbt.py). Доказательства: `rpc-results.json`, успешный workflow после коррекции только scratch-import — `workflow-results.json`.

Исправление: разделить пассивный watch-only import и создание нового multisig wallet. Для второго — отдельный blank wallet, active receive/change descriptors, правильный next_index и выбор wrapper/change type. Для конкретного нерейнджевого адреса active:false остаётся корректным.

### B-08 · P2 · Корректные Taproot pkh-листья отвергаются

[musig-descriptor.ts:228](../../apps/psbt-inspector/src/musig-descriptor.ts).

Два официальных положительных примера с `tr(...,pkh(...))` дают `P2TR: invalid leaf script=pkh`. Core 31.1 принимает оба и выдаёт адреса. Причина — ограничение классификатора leaf script в Scure; существующий allowUnknownOutputs не помогает для уже распознанного типа pkh.

Эталон: [descriptor_tests.cpp:1157](https://github.com/bitcoin/bitcoin/blob/a604a7647588500354d4772e60620ea36b129d05/src/test/descriptor_tests.cpp#L1157), также строка 1159. Доказательства: `descriptor-results.json`, `additional-results.json`, оба браузера.

Исправление: интегрировать корректно проверенные Tapscript leaves без смешения классификатора обычного output script с консенсусом Tapscript; проверить дерево/хеш/адрес по этим двум векторным результатам. Не отключать все проверки скриптов без замены.

### B-09 · P2 · Декодер принимает синтаксически неправильные descriptors

[descriptor.ts:74](../../apps/psbt-inspector/src/descriptor.ts), [descriptor-compiler.ts:110](../../apps/psbt-inspector/src/descriptor-compiler.ts).

Официальные отрицательные примеры `addr(asdf)`, `sh(<pubkey>)`, `multi(+1,...)` принимаются. Первые два заканчиваются без compiledOutput, а не понятной ошибкой; третий реально компилируется благодаря числовому приведению. Core отвергает все три. `addr(asdf)` подтверждён в двух браузерах.

Эталон: [descriptor_tests.cpp](https://github.com/bitcoin/bitcoin/blob/a604a7647588500354d4772e60620ea36b129d05/src/test/descriptor_tests.cpp#L1018), строки 1018/1029/1053. Исправление: строгая грамматика и проверка адреса выбранной сети; отделять «известный формат, но не реализовано представление» от «синтаксически недопустимо». Доказательства: `descriptor-results.json`, `rpc-results.json`.

### B-10 · P2 · Staged recovery P2TR теряет ranged xpub при экспорте

[policy.ts:371](../../apps/psbt-inspector/src/policy.ts), [policy.ts:407](../../apps/psbt-inspector/src/policy.ts).

При входных `xpub/<0;1>/*` строится portableDescriptorBody, но для P2TR его заменяет готовый конкретный taprootDescriptor. Core сообщает `isrange:false`; изменение индекса меняет сам descriptor. Для тех же исходных данных в P2WSH descriptor остаётся ranged. Это расходится с README о сохранении ranged export.

Доказательство: `final-results.json`, `staged`: P2WSH индексы 0/1 → isrange=true; P2TR индексы 0/1 → false. Адрес текущего конкретного индекса при этом корректен.

Исправление: сохранять исходные key expressions и binary tree в Taproot export, отдельно показывая материализованный текущий адрес; проверить receive/change и несколько индексов через deriveaddresses.

### B-11 · P2 · Разные origin paths ошибочно запрещены

[multisig-wallet.ts:314](../../apps/psbt-inspector/src/multisig-wallet.ts).

Два cosigner xpub с origin `m/48h/1h/0h/2h` и `m/48h/1h/1h/2h` отвергаются. Core принимает их вместе и выводит общий multisig. Origins описывают происхождение каждого ключа; совпадение account path у всех участников не является правилом Bitcoin multisig. Текст ошибки дополнительно содержит Dash-only пример для Bitcoin.

Доказательство: `additional-results.json`, `mixed_account_origins`. Исправление: валидировать каждое origin отдельно; при необычной комбинации давать предупреждение, сохраняя обязательную сверку descriptor/адресов всеми участниками. Не запрещать допустимую комбинацию автоматически.

### B-12 · P2 · Обещанный P2WSH с 17–20 ключами не работает

[policy.ts:67](../../apps/psbt-inspector/src/policy.ts).

Верхний уровень и README допускают до 20 ключей, но общий validatePublicKeys ограничивает 16. Пробы 15/16 проходят, 17/20 завершаются ошибкой. Core принимает P2WSH sortedmulti с 16, 17 и 20 ключами.

Доказательства: `edge-results.json`, `policy-matrix-results.json`. Исправление: ограничения по wrapper/context плюс script-number encoding выше OP_16; сохранить P2SH-предел 520 байт и 15 compressed keys. Одного изменения числа в проверке недостаточно без векторов для скомпилированного скрипта.

### B-13 · P3 · CLI-экспорт не включает выбранную сеть

[multisig-wallet.ts:164](../../apps/psbt-inspector/src/multisig-wallet.ts), [multisig-wallet.ts:379](../../apps/psbt-inspector/src/multisig-wallet.ts).

При testnet/regtest генерируется `bitcoin-cli importdescriptors ...` без сетевого флага. Команда использует сеть конфигурации CLI, обычно mainnet. С literal pubkey descriptor сеть нельзя распознать из текста, поэтому такой импорт способен успешно попасть в другую сеть. На xpub неверной сети чаще получится явная ошибка, но это не делает экспорт самодостаточным.

Доказательство: `edge-results.json`, network_mainnet/testnet/regtest. Исправление: корректные сетевые флаги или явное требование выбора CLI chain. Testnet и signet используют одинаковые адресные версии, поэтому текущая объединённая UI-модель не позволяет автоматически угадать нужный флаг; это нужно решить явно.

## Что не следует считать найденной ошибкой

- Приём корректных unknown PSBT fields необходим для совместимости. B-03 относится только к повреждённому формату proprietary key.
- Неустановленная UTXO-сумма и отсутствие BIP32 origins не делают каждый PSBT синтаксически невалидным.
- Декодирование несанационной политики с явным предупреждением полезно; создание переносимого Core wallet из неё — отдельное требование.
- Hardened child derivation из одного xpub невозможна. Семь соответствующих C++ положительных векторов проверяют контекст с доступными private keys; наш public-only инструмент этим контекстом не обладает.
- `combo()` задаёт несколько output scripts; отсутствие одного compiledOutput не означает неверный вычисленный адрес. Это ограничение представления.
- Изначальное подозрение о версии транзакции `0xffffffff` не подтверждено как расхождение с Core31.1: обе реализации показывают 4294967295. В список дефектов оно не включено.

## Порядок исправлений и регрессии

1. B-01/B-02: убрать ложные утверждения о подписи; отдельно проверять legacy/BIP143/BIP341 и конфликтующие metadata.
