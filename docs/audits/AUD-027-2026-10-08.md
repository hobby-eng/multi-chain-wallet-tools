#### AUD-022-UI001 — Medium — MHFE Check verdict is not bound to its current fields

- **Category:** UI
- **Status:** open
- **Release blocking:** True
- **Reproduction:** Run the real Check tab with a synthetic successful check; defer only the final walletParameters request, edit the fingerprint, then resolve parameters.
- **Expected:** Editing clears the old assurance and its late completion cannot certify current fields.
- **Observed:** A fingerprint edited while final walletParameters waits is followed by Matches for the old fingerprint.
- **Impact and limitations:** Misleading recovery rehearsal for the current written backup/reference. This is verdict attribution, not an incorrect cryptographic comparison.
- **Evidence:** late-publication-complete-fixture: first failed test
- **Recommended fix:** Recheck input revision after final parameters resolve, immediately before result mutation; preserve no-length answer events as job questions.
- **Required verification:** Replay the bounded real-tab deferred-parameters regression, plus unchanged completion and Cancel/reset variants of Encode/New wallet.

- **Category:** API
- **Status:** open
- **Release blocking:** False
