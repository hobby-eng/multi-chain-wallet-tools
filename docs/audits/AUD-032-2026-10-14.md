### Findings

#### AUD-032-BLD002 — Medium — A build without MnemoCode refuses the shared standard SSKR seed-width module

- **Category:** BLD.
- **Status:** verified within named targeted scope; uncommitted source.
- **Release blocking:** false for this defect; overall release gates remain unresolved.
- **Affected files:** `tooling/key-derivation-composition.mjs`.
- **Reproduction:** Build the Dash Deriver with --exclude mnemocode while its standard SSKR feature remains selected.
- **Expected:** Remove MnemoCode panels and operations while standard SSKR keeps the exact shared policy constants it needs.
- **Observed:** The selective-no-mnemocode command failed on source/sskr/share-platform.ts, imported for SEED_BYTES by the standard host.
- **Impact:** A supported selective build fails to compile. No spending-authority or secret-isolation compromise was demonstrated.
- **Fix:** Allow that exact shared input only when the real standard SSKR host is present; preserve negative checks for absent SSKR and unrelated MnemoCode code.
- **Required verification:** Compile the affected selective artifact and retain source-graph positive/negative controls.
- **Evidence:** local AUD-032-evidence/selective-no-mnemocode.command.json; tooling/mnemocode-shared-admission.test.mjs.

#### AUD-032-API001 — Medium — Group values are read repeatedly before byte packing

- **Category:** API.
- **Status:** verified within named targeted scope; uncommitted source.
- **Release blocking:** false for this defect; overall release gates remain unresolved.
- **Affected files:** `packages/recovery-backup/src/sskr-groups.ts`.
- **Reproduction:** Pass a group whose threshold getter changes after its first read. The original constructor repeatedly validates getters and rereads them for Uint8Array.from.
- **Expected:** Capture each threshold/count once, validate that snapshot with CheckedSskrBridge.groupSpecifications, then pack its admitted bytes.
- **Observed:** The before-fix test rejected an initially valid snapshot on a later getter read. Source review also establishes that a value changing only during packing can bypass the validated snapshot.
- **Impact:** Programmatic group objects can be refused inconsistently or change their packed meaning. UI-created plain records are a narrower case; no recovery loss was demonstrated.
- **Fix:** Snapshot the group values and delegate member admission and protocol constants to the shared library.
- **Required verification:** Single-read getters, 258/259, fractional/negative/NaN refusals, unchanged Envelope group text and official grouped SSKR controls.
- **Evidence:** local AUD-032-evidence/sskr-before.command.json; packages/recovery-backup/tests/sskr-bridge-boundary.test.ts; packages/recovery-backup/tests/sskr-groups.test.ts.

#### AUD-032-SEC001 — Low — Unsupported SSKR selectors are repeated and coerced in host refusals

- **Category:** SEC.
- **Status:** verified within named targeted scope; uncommitted source.
- **Release blocking:** false for this defect; overall release gates remain unresolved.
- **Affected files:** `packages/recovery-backup/src/sskr-codec.ts`.
- **Reproduction:** Call SskrCodec.create with the synthetic unknown selector used in sskr-bridge-boundary.test.ts. The before-fix refusal contains that supplied text; object selectors reach String().
- **Expected:** Refuse an unsupported selector with an owned stable code and constant safe text, without coercion.
- **Observed:** The before-fix fixture failed on selector echo. The original adapter explicitly formatted String(encoding).
- **Impact:** A value pasted into the wrong field can be repeated in failure presentation. No network disclosure, real secret or wallet compromise was demonstrated.
- **Fix:** Use the codec's one error catalog and an own-key string admission check.
- **Required verification:** Unknown text and object selector privacy controls through the real codec; immutable coded host errors.
- **Evidence:** local AUD-032-evidence/sskr-before.command.json; packages/recovery-backup/tests/sskr-bridge-boundary.test.ts.

#### AUD-032-SEC002 — Low — Host image conversion leaves refused or partial output buffers uncleared

- **Category:** SEC.
- **Status:** verified within named targeted scope; uncommitted source.
- **Release blocking:** false for this defect; overall release gates remain unresolved.
- **Affected files:** `packages/recovery-backup/src/mnemocode-cards.ts`, `packages/recovery-backup/src/mnemocode-card-files.ts`.
- **Reproduction:** The original image converter obtains its rasterizer before the PDF cleanup scope, never clears a rejected multi-page result, and accumulates individual outputs without failure cleanup. Sample conversion also retains its source PDF.
- **Expected:** An owner clears the input PDF on every image conversion exit and clears prior outputs/unprocessed PDFs after a later refusal; successful output transfers to its caller.
- **Observed:** Source paths lacked those cleanup scopes. The new bounded byte fixtures exercise missing conversion, multi-page refusal, late failure, invalid components and successful transfer without rendering PDFs.
- **Impact:** Recovery-bearing temporary bytes can outlive the refused export until garbage collection. This is a memory-lifetime defect, not demonstrated exfiltration; JavaScript erasure remains best effort.
- **Fix:** One MnemoCodeCardFiles owner for conversion, partial file-set cleanup and archive packing.
- **Required verification:** Tiny synthetic buffer cleanup and ownership fixtures plus existing page job/plan lifecycle regressions.
- **Evidence:** packages/recovery-backup/tests/mnemocode-card-files.test.ts; apps/key-derivation/tests/mnemocode-card-job-lifecycle.test.ts.

#### AUD-032-UI001 — Low — Candidate-list save failure is labelled as saved

- **Category:** UI.
- **Status:** verified within named targeted scope; uncommitted source.
- **Release blocking:** false for this defect; overall release gates remain unresolved.
- **Affected files:** `apps/key-derivation/src/ui/recovery-mnemocode-candidates.ts`.
- **Reproduction:** Force the download boundary to throw. The old finally block always labelled the disabled button Candidate list saved.
- **Expected:** State that saving failed, wipe the list and stop any repeat save of wiped bytes.
- **Observed:** The success label was in finally irrespective of download success.
- **Impact:** A failed recovery-list download can look successful. The host cannot confirm a browser's eventual filesystem publication, so the new message covers the synchronous save boundary only.
- **Fix:** Set the success label only after the save call; handle the refusal with a safe failure message and keep cleanup in finally.
- **Required verification:** The actual controller reports failure, clears bytes and disables its button under a synthetic save refusal.
- **Evidence:** apps/key-derivation/tests/mnemocode-list-save.test.ts.
