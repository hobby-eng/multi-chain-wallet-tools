## Review evidence

### Scope and methodology

Reviewed the MnemoCode part of the Key Derivation Tool in both editions: the adapter `packages/recovery-backup/src/mnemocode.ts`, the card adapter `mnemocode-cards.ts` with its browser platform (random source, QR matrix, PNG coding, ZIP file), the panel and card form under `apps/key-derivation/src/ui/`, the way a phrase from Generate & Derive reaches the panel, the synchronization command `tooling/sync-mnemocode-source.mjs`, and the documents and the release passport that describe these parts. The mnemonic validation in `packages/crypto-core/src/bip39.ts` was read because the panel shows its messages.

Method: source reading, then edge-case probes through the adapter with the public test phrase `abandon … about` in a temporary test file that was removed afterwards. No real secret was used.

Not in scope: every other tool and recovery format, coin derivation, PSBT inspection, public-data tools, the WASM modules, the reproducible Docker build, and the release workflow.

No evidence folder is kept. The evidence is the commands below and the regression tests named in each finding.

### Findings

#### AUD-018-SEC001 — Low — An error about an unknown BIP39 word shows the word

- **Category:** SEC.
- **Severity:** low.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `packages/crypto-core/src/bip39.ts`; every tool that validates a phrase.
- **Reproduction:** enter a phrase in which one word is mistyped.
- **Expected behavior:** the message names the position of the word, as MnemoCode itself does.
- **Observed behavior:** the message contained the word: `Unknown word: …`.
- **Impact:** a mistyped word is close to a secret one and appeared in open text on the screen. It left the page only if the person copied the message. The behaviour is older than the reviewed change.
- **Evidence:** source inspection; `packages/crypto-core/tests/bip39-bip32.test.ts`, "names the position of an unknown word and never the word".
- **Recommended fix:** name the position.
- **Required verification:** the message contains the position and not the word.

#### AUD-018-SEC002 — Low — Card documents stay in memory after the download

- **Category:** SEC.
- **Severity:** low.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `packages/recovery-backup/src/mnemocode-cards.ts`, `apps/key-derivation/src/ui/recovery-mnemocode-cards.ts`.
- **Reproduction:** export cards and follow the byte arrays after the download starts.
- **Expected behavior:** buffers that hold recovery material are cleared after use, as the neighbouring modules do.
- **Observed behavior:** the PDF, the ZIP file and the separate documents were left to the garbage collector.
- **Impact:** recovery material stayed in page memory longer than needed. A browser gives no guarantee that memory is erased, so clearing reduces the time and does not remove the risk.
- **Evidence:** source inspection; `packages/recovery-backup/tests/mnemocode-cards.test.ts`, "clears the separate documents after they are packed".
- **Recommended fix:** fill the arrays with zeros once the file is handed to the browser.
- **Required verification:** the archive still holds valid documents after the working copies are cleared.

#### AUD-018-API001 — Low — The 64 KiB input limit is not applied to encoding and card export

- **Category:** API.
- **Severity:** low.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `packages/recovery-backup/src/mnemocode.ts`.
- **Reproduction:** call `encodeMnemoCode` or the card exporter with a phrase, or dates, longer than 64 KiB.
- **Expected behavior:** the limit stated in the comment of the module applies to every input.
- **Observed behavior:** only decoding applied it. A phrase of 5 MB was still refused in 118 ms by the word count check.
- **Impact:** none observed; the comment promised more than the code did.
- **Evidence:** the probe output; `mnemocode-cards.test.ts`, "applies the input limit before any work starts".
- **Recommended fix:** apply the limit in `encodeMnemoCode` and `parseMnemoCodeDate`.
- **Required verification:** each call fails with the limit message before any work starts.

#### AUD-018-API002 — Low — A card request can ask for a sheet size and separate cards at once

- **Category:** API.
- **Severity:** low.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `packages/recovery-backup/src/mnemocode-cards.ts`.
- **Reproduction:** request `pageSize: 'a6'` with `output: 'individual'`, or a card size with `output: 'collection'`.
- **Expected behavior:** the page size alone decides between one sheet and separate cards.
- **Observed behavior:** the first request gave eight cards of A6 size in a ZIP file, the second a PDF of eight pages.
- **Impact:** the form could not send such a request, but the interface allowed it.
- **Evidence:** the probe output; `mnemocode-cards.test.ts`.
- **Recommended fix:** remove `output` from the request and derive it from the page size.
- **Required verification:** the request type has no `output`; the tests pass without it.

#### AUD-018-BLD001 — Medium — Synchronization takes the identifier of an annotated tag, not its commit

- **Category:** BLD.
- **Severity:** medium.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `tooling/sync-mnemocode-source.mjs`.
- **Reproduction:** give the tag selection a `git ls-remote` listing with an annotated tag.
- **Expected behavior:** the commit behind the tag, which the listing shows on the line ending in `^{}`.
- **Observed behavior:** the identifier of the tag object was used as the commit.
- **Impact:** the first signed or annotated release tag of MnemoCode would have stopped the synchronization, or pinned an identifier that is not a commit. No such tag exists yet.
- **Evidence:** source inspection; `tooling/sync-mnemocode-source.test.mjs`, "takes the commit behind an annotated tag, not the tag itself".
- **Recommended fix:** prefer the peeled line.
- **Required verification:** the test with both lines selects the commit.

#### AUD-018-BLD002 — Low — A full commit is not checked to be part of the MnemoCode main branch

- **Category:** BLD.
- **Severity:** low.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `tooling/sync-mnemocode-source.mjs`.
- **Reproduction:** run the synchronization with `--ref` and the full identifier of a commit that exists only in a fork.
- **Expected behavior:** only commits of the MnemoCode repository are accepted.
- **Observed behavior:** GitHub serves the files of any commit in the network of a repository, and the command accepted them.
- **Impact:** a developer who is given a wrong identifier could vendor code from a fork. The developer still reviews and commits the result.
- **Evidence:** source inspection; `sync-mnemocode-source.test.mjs`, "accepts a full commit only when the main branch contains it".
- **Recommended fix:** ask GitHub to compare the commit with `main` and accept only `ahead` or `identical`.
- **Required verification:** `diverged`, `behind` and a missing commit are refused.

#### AUD-018-UI001 — Low — Dates left in the hidden field block Direct mode

- **Category:** UI.
- **Severity:** low.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `packages/recovery-backup/src/mnemocode.ts`, `apps/key-derivation/src/ui/recovery-mnemocode-cards.ts`.
- **Reproduction:** type dates in a Seedshift mode, switch to Direct, then encode; or decode a Direct record while the form still holds dates.
- **Expected behavior:** Direct mode ignores dates.

- **Evidence:** the probe output; `packages/recovery-backup/tests/mnemocode.test.ts`, "needs a four-digit year and ignores dates for a Direct record".
- **Recommended fix:** pass no dates in Direct mode.
- **Required verification:** a Direct record decodes while the form holds dates.

#### AUD-018-ARC001 — Low — The browser check for words of the phrase in a PDF cannot fail

- **Category:** ARC.
- **Severity:** low.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `tooling/verify-browser-regressions.mjs`.
- **Reproduction:** read the assertion that the bytes of the PDF do not contain the first word of the phrase.
- **Expected behavior:** a check that would fail if a word were printed.
- **Observed behavior:** a PDF stores its text compressed and as glyph numbers, so the bytes never contain a word.
- **Impact:** the test gave assurance that it could not give.
- **Evidence:** source inspection; `mnemocode-cards.test.ts`, "prints the color codes and nothing of the phrase".
- **Recommended fix:** read the text of the PDF with `pdftotext` and compare words.
- **Required verification:** the new test passes where Poppler is installed. It is skipped, and reported as skipped, where Poppler is missing, as on the CI runner.

#### AUD-018-ARC003 — Low — The MnemoCode version is written as text in the page
