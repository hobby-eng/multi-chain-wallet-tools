## Findings

### AUD-017-API002 — Low — Discovery CSV `balance_display` remains empty for non-Dash adapter results without `balanceUnit`

- **Category:** API.
- **Severity:** low.
- **Status:** verified on 2026-10-02 (open at the reviewed snapshot; this is the original ID, not a duplicate new finding). See the remediation section.
- **Release blocking:** false. Exact `balance_atomic`, asset, and decimal metadata are not lost; the human-readable CSV column is blank.
- **Affected files and builds:** `apps/discovery-scanner/src/export.ts`; Bitcoin and Ethereum seed/watch-only result adapters in `apps/discovery-scanner/src/coins/`.
- **Reproduction:** The current Bitcoin and Ethereum finding constructors set a `bigint` `balanceAtomic` and a formatted `balanceLabel` but do not set optional `balanceUnit`. Pass those same public-result shapes to the production `createRecoveryExport(..., "csv")` entry point with synthetic values `12345678n`, `0.12345678 BTC`, and `0.000000000012345678 ETH`.
- **Expected behavior:** `balance_display` contains the exact decimal amount for each supported coin.
- **Observed behavior:** `findingBalanceDisplay` formats `balanceAtomic` only when `balanceUnit` exists; its fallback, `numericDash`, recognizes only a `DASH` suffix. Both non-Dash rows have an empty `balance_display` cell. The harness passes by asserting this observed defect.
- **Impact:** A user reading the generic CSV display column cannot scan BTC/ETH amounts. The exact integer and unit columns remain available, so this is a bounded presentation/export defect, not monetary-value corruption.
- **Evidence:** local `historical-api-regressions-final.log`, 2/2 reproduction cases; source review of the Bitcoin and Ethereum result constructors and `findingBalanceDisplay`.
- **Recommended fix:** Populate `balanceUnit` with the coin's exact asset/atomic unit/decimals in both adapters, or format through a required unit-aware export contract. Avoid guessing from display labels.
- **Required verification:** Add active-path BTC/ETH export assertions using actual adapter-produced result objects, preserve exact atomic values, and verify all supported assets plus a synthetic future adapter.
