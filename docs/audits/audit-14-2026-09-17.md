## 2. New finding

<a id="h-01--high--committed-sskr-and-envelope-wasm-are-not-the-canonical-container-output-docker-build-fails"></a>

### AUD-014-BLD001 — High — Committed SSKR and Envelope WASM are not the canonical container output; Docker build fails

- **Observed:** `docker build --no-cache … --target artifacts` for `e6a6d6b` passes `pnpm verify` and the matrix smoke, then fails at `Dockerfile.reproducible` `diff --recursive --brief …` with `Files /tmp/committed-generated/sskr/recovery_sskr_wasm_bg.wasm and packages/recovery-sskr-wasm/generated/recovery_sskr_wasm_bg.wasm differ` (12:09 UTC). Extracting the `built` stage: SSKR container 394 954 B (`0d6f8e75…`) vs committed 389 084 B (`30e314a4…`); Envelope container 846 163 B (`817a2291…`) vs committed 840 314 B (`c02e931c…`). Glue `.js`/`.d.ts` files are identical; producer strings are `0.2.128` on both sides; `Cargo.lock` is identical; embedded `rustc` commit is the same (`48a229ce…`, 1.98.1). The difference is in code, not metadata.
- **Cause:** both crates' `lib.rs` changed in this commit and both generated modules were regenerated on the developer host (SSKR 387 393 → 389 084 B, Envelope 841 797 → 840 314 B; local `target/` timestamp 14:28, commit 14:53). Those bytes do not match the container's, so the host build environment differs from the canonical one in something the producer check does not see (candidates: `CARGO_ENCODED_RUSTFLAGS`/cfg differences such as the `getrandom_backend` cfg, or a differently built `wasm-bindgen`/LLVM). Orchard, Shamir and Codex32, which were not touched, still match.
- **Impact:** CI, release workflow and `./tooling/build-reproducible.sh` fail on this commit; no canonical artifacts or attestations can be produced. Functionally the modules are equivalent (all tests and the browser matrices pass with the committed bytes).
- **Correction:** regenerate all five modules through `./tooling/build-reproducible.sh --wasm` and commit the result. Strengthen the gate: `verify-wasm-producers` cannot detect this; add to `pnpm verify` a check that each committed `.wasm` hash equals the hash recorded in the last successful container run (or make `verify:ci` diff against the container output, which is what the Dockerfile already does — but locally `pnpm verify` should refuse to succeed when `packages/*/rust/src` is newer than `generated/`).
