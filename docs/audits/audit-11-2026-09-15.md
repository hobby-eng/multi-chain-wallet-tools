## 2. New findings

### N-01 — High — Committed WASM binaries are not the canonical container output; uncached Docker build fails at the WASM diff

- **Files:** `packages/dash-shielded-wasm/generated/dash_shielded_wasm_bg.wasm`, `packages/recovery-shamir-wasm/generated/recovery_shamir_wasm_bg.wasm`, `packages/recovery-codex32-wasm/generated/recovery_codex32_wasm_bg.wasm` (all last changed in commit `f064ce3`, "feat: modularize selectable wallet tool builds").
- **Observed:** `docker build --no-cache … --target artifacts` (19:06–19:12 UTC) passes every verification layer and then fails at `Dockerfile.reproducible:73` (`diff --recursive --brief /tmp/committed-generated/dash …`): `Files … dash_shielded_wasm_bg.wasm differ`. Extracting the container's regenerated files (`--target built`) shows all three `.wasm` differ from HEAD by 12 bytes each while every `.js`/`.d.ts` file is identical. The only differing content is the WebAssembly `producers` section: HEAD carries `0.2.128 (92201b377)` (a wasm-bindgen CLI built from a Git checkout), the container carries `0.2.128` (the crates.io CLI installed by the Dockerfile). At the previously audited commit `d978dd4d` the Orchard binary was `defbee28…` with producer `0.2.128`, i.e. canonical; commit `c46b179` ("Match crates.io CLI producer metadata in committed WASM") had already fixed this exact issue once, and `f064ce3` reintroduced it for Orchard and shipped the two new modules the same way.
- **Impact:** CI, the release workflow and `./tooling/build-reproducible.sh` fail on this tree; no canonical artifacts or attestations can be produced. Functionally the binaries are equivalent (same code sections; local and container builds pass all tests), so this is a provenance/reproducibility defect, not a behavioural one.
- **Note on the earlier cached build:** a cached `docker build` at 19:02 UTC reported success because BuildKit reused a `verified` layer produced from a context that contained the container-matching binaries; that run is not evidence for the current tree.
- **Correction:** regenerate the three modules through the canonical path (`./tooling/build-reproducible.sh --wasm`) and commit those bytes (they equal the `defbee28…`/`3fe873ac…`/`afeb2474…` files seen in the working tree at 19:02 UTC), then re-run the uncached Docker build. Add a check to `verify-shielded-wasm`/artifact verification that the `producers` section of every committed `.wasm` equals the pinned CLI string, so a locally regenerated binary fails fast without Docker.
