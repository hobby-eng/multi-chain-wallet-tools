# CKD Shamir share format

CKD Shamir Raw and CKD Shamir Words are versioned application formats around GF(256) shares generated by the pinned Rust `sharks` implementation. They are not SLIP-39, SSKR, Codex32, or ordinary BIP39 recovery phrases. Use SLIP-39 when interoperability with wallet software is required.

This specification is developer documentation. Generated cards intentionally contain no visible `ckd-*` prefix. Removing a visible label is a presentation choice, not steganography: the decoded binary envelope remains identifiable by its magic and structure.

## Version 2 envelope

Each card encodes one complete binary envelope, in this order:

| Field            |             Bytes | Meaning                                                     |
| ---------------- | ----------------: | ----------------------------------------------------------- |
| Magic            |                 4 | ASCII `CKDS` (`43 4b 44 53`)                                |
| Version          |                 1 | `02`                                                        |
| Threshold        |                 1 | Required distinct shares, 2–255                             |
| Share count      |                 1 | Generated share count, threshold–255                        |
| Secret length    |                 1 | 16, 20, 24, 28, or 32 bytes                                 |
| Set ID           |                 8 | WebCrypto-random identifier shared by the set               |
| Secret digest    |                16 | First 16 bytes of SHA-256 of the reconstructed entropy      |
| Serialized share | secret length + 1 | `sharks` share identifier followed by its share bytes       |
| Card checksum    |                 4 | First 4 bytes of SHA-256 over every preceding envelope byte |

The decoder checks the card checksum, version, declared bounds, exact non-padding length, set ID, threshold/count/secret-length agreement, distinct share identifiers, the threshold, and the v2 secret digest. Temporary entropy, randomness, digest, decoded envelope, and WASM result buffers are wiped on normal and exceptional exits.

## Encodings

- **Raw:** unpadded Base64URL of the complete envelope.
- **Words:** the complete envelope is read as an 8-bit stream and represented by indices in the English BIP39 2,048-word list. The final partial 11-bit group is zero-padded and the decoder rejects non-zero trailing padding.

The Words encoding uses the BIP39 dictionary only as a human-readable base-2048 alphabet. A Words card is not a BIP39 mnemonic and ordinary wallet software cannot reconstruct the original wallet from one card.

## Legacy version 1 import

The decoder accepts old v1 Raw values prefixed with `ckd-shamir-v1:` and old v1 Words values prefixed with `ckd-shamir-words-v1:`. New output never emits these prefixes and always uses v2.

Version 1 has the same base header, serialized share, and per-card checksum but no secret digest. Its checksum detects accidental damage to each card; it cannot provide the v2 guarantee that a checksum-valid substituted share reconstructs the intended entropy. The UI marks a v1 restoration with an explicit legacy integrity warning. Legacy acceptance exists only in the restore path and must not be used for new backups.
