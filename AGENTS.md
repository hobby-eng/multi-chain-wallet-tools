# multi-chain-wallet-tools agent instructions

This repository is part of the `bip_tools` workspace. If a workspace `AGENTS.md` exists one directory above this repository, read and follow it first. Its core rules: edit only this checkout in place, never create another copy or worktree, never delete project directories, use the toolchains it names, use only public test data, do not commit or push without an explicit request, and write everything in English only (code, comments, commits, documentation).

## Commands

- Install: `pnpm install --frozen-lockfile` (pnpm 12.18.0 via Corepack; Node 26.13.0 from `.node-version`; Python 3 with RIPEMD-160 in `hashlib` for the oracles of `pnpm test:vectors` and `pnpm verify`).
- Targeted: `pnpm check`; `pnpm exec vitest run <file>`; `pnpm test:vectors`; `pnpm test:self-test`.
- Release-level (explicit request only): `pnpm verify` or `pnpm verify:ci`; `./tooling/build-reproducible.sh` (Docker); `pnpm test:browser:files`, `pnpm test:browser:regressions`, `pnpm test:browser:selective`; `pnpm build:matrix:plan`, `pnpm build:matrix:smoke`.
- WASM regeneration only with `./tooling/build-reproducible.sh --wasm` and only when asked; committed generated bytes are canonical.
- Rust: the `CARGO_HOME` and `RUSTUP_HOME` set in the environment (never the home-directory defaults) (honoured by `tooling/rust-toolchain.mjs`).

## Audits

An audit, a review of findings or a remediation follow-up of this repository follows the workspace's audit procedure in `../.github/audits/`: `FULL_AUDIT_GUIDE_V2.md` (the checks and their order; section 17 for Rust crates, here the launcher and the WASM crates, and every target they are built for), `AUDIT_STANDARD.md`, `AUDIT_TEMPLATE.md` and `audit-report.schema.json`. Section 17 asks for `docs/audits/TARGETS.md` with the targets, their runners and the fuzzing budgets; until this repository has one, the audit derives the targets as section 17.3 says and records the missing file. This repository's `docs/FULL_AUDIT_GUIDE.md`, and the standard, template and schema in `docs/`, are version 1, kept for the reports that recorded their hashes. Reports, their JSON twins and their harnesses stay in this repository's `docs/audits/`.
